# InkKeep 使用說明

[English](user-guide.md) | 繁體中文

## 叫出視窗

點執行檔、按 `Alt+.`，或從系統匣圖示選「顯示視窗」。

快捷鍵只負責叫出視窗，再按一次不會收起。每次叫出來都會回到目前使用中螢幕的正中央。

按 `Esc` 或標題列的 ✕ 會收起視窗，程式留在系統匣。要結束程式，從系統匣選單選「離開」。

視窗是一般的 Windows 視窗：有標題列、可以最小化和最大化、會出現在工作列，不會永遠置頂。

程式已經在執行時再點一次執行檔，不會開第二個。保險庫開著就只跳通知說已在背景執行，還沒開就叫出視窗。

## 兩層金鑰

主密碼跑兩次不同 salt 的 Argon2id，得到兩把互相推導不出來的金鑰。

| | 第一層 | 第二層 |
|---|---|---|
| 保護什麼 | 整個 kdbx：片語、書籤、標題、帳號 | 只有密碼項目的密碼欄位 |
| 存哪裡 | Windows 認證管理員 | 不存，每個 session 需要時重新推導 |
| 什麼時候要你輸入 | 換一台電腦的第一次 | 每次閒置鎖定之後第一次**讀**密碼 |

平常開 InkKeep 直接進搜尋，片語與書籤立刻能用。

第二層是一組公鑰和私鑰。公鑰存在保險庫裡，所以新增、改寫密碼都不必輸入主密碼。私鑰每次從主密碼重新推導，不存到任何地方，要讀回密碼時才需要它：

| 動作 | 要主密碼嗎 |
|---|---|
| 新增密碼、改寫密碼 | 不要 |
| 改標題、帳號、標籤 | 不要 |
| 送出密碼（Enter）、複製密碼 | 要 |
| 在編輯畫面按「顯示」看原文 | 要 |
| 送出或複製帳號、網域 | 不要，它們沒有加密 |

編輯既有的密碼項目時，密碼欄位是空的。留空就沿用原本的密碼。

輸入一次主密碼之後，到閒置鎖定前都不會再問。

公鑰只能加密：拿得到第一層金鑰的人可以新增或覆蓋密碼項目，但讀不到既有的密碼。

換一台電腦只要記得主密碼。在新電腦輸入一次，金鑰就會存進那台的認證管理員。

第一層的金鑰存在認證管理員裡，由 DPAPI 以你的登入憑證保護：換一個 Windows 帳號讀不出來，把硬碟拔到別台機器也讀不出來。想關掉這個快取，設定頁有「每次啟動都詢問主密碼」。

**讀取密碼項目一定要主密碼。** 片語與書籤用認證管理員裡的金鑰就讀得到。

## 搜尋

下表是預設的快捷鍵。設定頁的「快捷鍵設定」可以逐一更改，點一下再按下新的組合、放開即可，改完立刻生效，全域的 `Alt+.` 也在那裡改。可以設成按住一個鍵再按另一個，例如 `Tab+↓` 是按住 `Tab` 再按 `↓`。「類別往左」預設沒有指定。

單按 `Tab` 在放開時才換類別：按住 `Tab` 接方向鍵時，不會先換一次類別。

| 鍵 | 動作 |
|---|---|
| 文字輸入 | 即時搜尋 |
| `#` | 開啟標籤選單，選一個加進搜尋條件 |
| `Tab` | 切換類別：片語 → 書籤 → 密碼 |
| `Tab+↓` / `Tab+↑` | 切換工作區：全部 → 各工作區 |
| `↑` `↓` | 選擇 |
| `PageUp` / `PageDown` | 一次移動 10 筆 |
| `Enter` | 送出。密碼項目有帳號時先問要送帳號還是密碼 |
| `Shift+Enter` | 只複製到剪貼簿 |
| `Ctrl+Enter` | 用預設瀏覽器開啟書籤（只開 http、https 網址） |
| `Ctrl+N` / `Ctrl+E` | 新增／編輯 |
| `Ctrl+,` | 設定 |
| `Ctrl+L` | 鎖定密碼（片語與書籤照常可用） |
| `Esc` | 關閉視窗 |

在搜尋框打 `#` 會跳出現有的標籤，繼續打字可以篩選；用 `↑` `↓` 選、`Enter` 或 `Tab` 確定、`Esc` 關掉。選好的標籤會在原位變成小方塊，跟文字混在同一行，可以加好幾個，每個都要符合。游標能停在方塊之間，`Backspace`、`Delete` 會把旁邊的方塊整個刪掉，也可以按方塊上的 ×。

沒從選單挑的 `#` 是普通文字，例如搜尋 `#include` 就是找內容裡有這串字的項目。

片語與書籤每一列右邊有複製和編輯鈕。密碼項目的複製鈕在右側預覽，帳號、網域、密碼各有一個。

搜尋規則：空白切 token，每個 token 都要出現在標題或內容裡；標題完全相符的排最前，其餘依使用次數降序。密碼項目只比對標題、帳號與網域，密碼本身不參與比對。

## 模板佔位符

只有片語會展開。

| 佔位符 | 說明 | 範例輸出 |
|---|---|---|
| `${date}` | 今天，ISO 格式 | `2026-09-23` |
| `${date:+7d}` | 偏移，單位 `d` `w` `m` `y` | `2026-09-30` |
| `${date::long}` | 格式：`iso`（預設）、`long`、`short`、或 strftime | `2026年9月23日` |
| `${date:+7d:long}` | 偏移與格式並用 | `2026年9月30日` |
| `${time}` / `${time:12h}` | 時間 | `18:34` / `下午6:34` |
| `${datetime}` | 日期時間 | `2026-09-23 18:34` |
| `${clipboard}` | 插入當下的剪貼簿文字 | |
| `${cursor}` | 送出後游標停在此處 | |
| `${input:標籤}` | 送出前彈出表單詢問 | |
| `${input:標籤:預設值}` | 附預設值 | |
| `${select:標籤:甲\|乙\|丙}` | 下拉選單 | |
| `${uuid}` | 隨機 UUID v4 | |
| `${snippet:另一個標題}` | 引用其他片語，深度上限 5 | |

寫 `$${` 可以輸出字面的 `${`。引數裡要用到 `:` `|` `}` 時前面加反斜線。

片語裡的大括號會原樣保留，例如 `fn main() { }`；只有 `${` 才是佔位符的開頭。

月／年偏移採日曆語意，溢位截斷到當月最後一天（1/31 加一個月得到 2/28）。

## 送出方式

| 類型 | 方式 |
|---|---|
| 片語、書籤 | 寫剪貼簿 → `Ctrl+V`，貼上後還原原本的剪貼簿文字 |
| 密碼、帳號 | `SendInput` 逐字輸入，不碰剪貼簿 |

密碼項目不管送帳號還是密碼，都逐字輸入。剪貼簿是全系統共享的，背景程式和剪貼簿歷史工具都讀得到，所以帳密不經過它。

還原會在貼上後 0.3 秒進行，讓目標程式先讀完。這段期間你自己複製了別的東西，就保留你複製的內容。原本剪貼簿裡是圖片或檔案時，還原後剪貼簿會是空的。

片語與書籤走剪貼簿時會設定三個排除標記，擋掉 Windows 內建的剪貼簿歷史（`Win+V`）與雲端剪貼簿，但擋不掉第三方剪貼簿管理員。

送出密碼的過程中每 32 個字元重新確認一次前景視窗，你中途切走就立刻中止。

## 工作區

片語、書籤、密碼都可以分工作區，例如「個人」和「公司」。搜尋框左邊的下拉選單選工作區，
選「全部」就一起搜。`Tab+↓`、`Tab+↑` 依選單順序切換。

- 每一筆都屬於一個工作區。第一次開檔時會自動建立「個人」，把原有的全部放進去
- 新增、改名、刪除在設定頁的「工作區」區塊；只能刪空的工作區
- 新增項目時預設放在搜尋畫面當下選的工作區，編輯畫面可以改
- 書籤與密碼匯入時選要匯入到哪一個。重複判斷只比對那個工作區，
  所以同一個網址可以同時放在「個人」與「公司」

每個工作區就是 kdbx 檔案裡的一個群組，其他 kdbx 工具打開會看到同樣的資料夾。

## 書籤匯入

設定頁「書籤匯入」的來源選單會列出這台電腦上每一個瀏覽器設定檔，用瀏覽器自己的名稱顯示，
例如「Chrome — John」「Chrome — 工作」。每個設定檔可以各自匯入到不同的工作區。

Chrome、Edge 的設定檔名稱取自 `User Data\Local State`，Firefox 的取自 `profiles.ini`。
訪客設定檔不列。Firefox 開著時也能匯入，包含剛加的書籤。

## 密碼匯入

設定頁「密碼匯入」→ 選要匯入到哪個工作區 → 選其他密碼管理器匯出的 CSV → 看筆數預覽 → 匯入。

不綁定特定來源，看標題列的欄位名稱判斷哪一欄是什麼。認得 Chrome、Edge、Firefox、
Bitwarden、1Password、KeePassXC、LastPass 的匯出格式；欄位名稱對得上的其他 CSV 也行。

- 不需要主密碼，密碼用保險庫的公鑰加密
- 資料夾（Bitwarden 的 folder、KeePassXC 的 group）變成標籤
- 網域加帳號跟同一個工作區裡既有項目重複的跳過
- 密碼欄空白的跳過
- 備註不會匯入，因為密碼項目沒有備註欄位；預覽會顯示有幾筆的備註沒有匯入

**匯出的 CSV 是明文。** 匯入完設定頁會提供「刪除這個 CSV 檔」，請用它刪掉，
也別把 CSV 放在會同步到雲端的資料夾。

瀏覽器的密碼請用瀏覽器自己的「匯出密碼」功能，InkKeep 不會直接去讀瀏覽器存密碼的檔案。

## 只能手改設定檔的選項

送出時的等待時間不在設定畫面裡，只有遇到某個程式送不進去、要排查時才需要調。
改 `settings.toml` 的 `[inject]`：

```toml
[inject]
focus_timeout_ms = 300      # 等焦點回到目標視窗的上限
paste_settle_ms = 30        # 貼上後到移動游標的等待
type_delay_ms = 2           # 逐字輸入的字元間隔
restore_delay_ms = 300      # 貼上後等多久還原剪貼簿
virtual_input = false       # 密碼改用掃描碼模擬實體按鍵
```

設定檔位置是 `%APPDATA%\app.inkkeep\settings.toml`。值超出範圍會被夾回合理區間，
程式照常啟動。改完要重新啟動。

## 已知限制

- 無法送進以系統管理員身分執行的視窗。這是 Windows 的 UIPI 機制：權限較低的程式不能對權限較高的視窗送輸入。遇到時會通知你，剪貼簿維持原本的內容。
- 中文輸入法開著時，虛擬鍵盤模式無效，掃描碼事件會被組字流程吃掉。預設的 Unicode 模式不受影響。
- 擋不住本機的惡意程式。以你的權限執行的程式讀得到本程式的記憶體，也能側錄鍵盤，任何密碼管理器都一樣。這個工具防的是雲端同步的檔案外洩、筆電遺失，以及別人短暫使用你的電腦。
- 能登入你 Windows 帳號的人讀得到片語與書籤，這是把第一層金鑰存在認證管理員、開 app 不必輸入密碼的取捨。密碼項目仍然要主密碼。想每次都輸入，就打開「每次啟動都詢問主密碼」。
- 記憶體清除只能盡量做。解鎖後金鑰留在記憶體裡；`zeroize` 保證清零的寫入不會被編譯器最佳化掉，但清不掉 `String` 重新配置時留下的舊副本和 CPU 暫存器裡的殘值，也擋不住被寫進 swap 或休眠檔。
- 用 DirectInput 的遊戲收不到模擬輸入。
- 遠端桌面內快捷鍵可能被本機用戶端截走。

## 資料格式

檔案裡的格式識別字（`snipkit-sealed:v1:`、`snipkit.secret.*` 等）保留舊名 `snipkit`，
那是它們當初寫入時的名字。已存的資料靠這些名字辨識，所以不跟著產品改名。

kdbx 4.1。三種類型各自落在原生欄位，所以用 KeePassXC 開起來是三種合理的條目：

| 類型 | kdbx 欄位 | KeePassXC 看到什麼 |
|---|---|---|
| 片語 | Notes | 內容原文 |
| 書籤 | URL | 網址原文 |
| 密碼 | Password（+ UserName、URL） | `snipkit-sealed:v1:…`；帳號與網域是原文 |

標籤存 Tags、使用次數存 UsageCount，都是 kdbx 原生欄位。在 KeePassXC 替項目加的備註等欄位，InkKeep 存檔時會保留。

密碼在 KeePassXC 裡看到的是密文，因為它多加密了一層（見「兩層金鑰」）。片語、書籤、標題與帳號在 KeePassXC 裡都是原文。

用 KeePassXC 開這個檔案時要貼的是**第一層金鑰**，不是主密碼。設定頁「保險庫金鑰」的「顯示」會印出來（要先輸入主密碼），CLI 是 `vault-key`。它由主密碼推導而來，每台電腦算出來的都一樣，不必抄下來保管。

存檔時先寫暫存檔，重新讀回逐欄比對，再輪替備份（保留 3 份），最後才覆蓋正本。比對不一致就保留暫存檔並回報錯誤，正本不動。`keepass` crate 的寫入功能比讀取新，所以多這一道檢查。

建議只用 InkKeep 寫入，KeePassXC 只拿來讀。兩邊都編輯也可以，但升級 `keepass` crate 時要重跑相容性測試。
